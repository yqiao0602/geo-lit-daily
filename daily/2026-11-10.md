### 🔥 ⭐⭐⭐⭐ SPyCE: Skill-Policy Co-evolution for Multimodal Agents
**8/10** · Ru Zhang、Weijie Qiu · ACM International Conference on Multimedia (ACM MM) · 2026-11-05 · [原文](https://doi.org/10.1145/3767308.3836256)
*入选：工作流×工具推理*

> 📄 **摘要**：Multimodal agents that think with images iteratively manipulate visual evidence and invoke tools across many steps. Existing reinforcement learning methods reduce trajectories to scalar rewards, forcing the policy to discover reusable tool-use patterns from scratch on every new task; memory-based alternatives retain past experience, yet they rely on test-time retrieval, without updating the policy to absorb reusable patterns from that experience. Our key insight is that multimodal reasoning trajectories should be distilled into reusable skills that co-evolve with the policy during training, rather than being consumed as rewards or retrieved from a static store. To this end, we propose SPyCE (Skill-Policy Co-evolution), a framework that distills trajectories into a hierarchical skill library and updates it throughout reinforcement learning. Execution skills capture local visual operations, while workflow skills encode high-level priors that orchestrate tool use. During training, the policy model conditions on retrieved skills to guide its rollouts, while the skill library evolves using valuable rollouts generated by the policy. This creates a closed loop in which improved policies yield better skills, and the evolving skill library, in turn, provides stronger priors for policy rollouts. Experiments across eight benchmarks demonstrate that SPyCE consistently outperforms both RL-based and memory-based baselines. Further analysis reveals that both the hierarchical skill design and the co-evolution mechanism are critical to our design. These results suggest joint skill-policy optimization as a promising paradigm for building capable multimodal agents.

**一句话**：提出 SPyCE 框架，把多模态 agent 的推理轨迹蒸馏成由执行技能和工作流技能组成的分层技能库，并让该技能库在强化学习过程中与策略协同演化。

痛点：现有 RL 方法把整条轨迹压缩成标量奖励，导致策略每遇到新任务都要从零摸索可复用的工具使用模式；而基于记忆的方法虽然保留历史经验，却依赖测试时检索，不会更新策略来吸收这些经验。方法：将轨迹蒸馏为分层技能库（execution skills 捕获局部视觉操作，workflow skills 编码编排工具使用的高层先验），训练时策略以检索到的技能为条件做 rollout，技能库又用策略产生的有价值 rollout 进化，形成策略与技能互相提升的闭环。结果：在八个基准上一致优于 RL 与 memory 两类基线，消融显示分层技能设计有效。

### ⭐⭐⭐ RM-VLM: From Natural-Language Task Descriptions to Vision-Grounded Reward Machines
**6/10** · Roko Parać、Christos Ziakas、Leo Ardon、Alessandra Russo · arXiv (Cornell University) · 2026-11-05 · [原文](https://doi.org/10.48550/arxiv.2611.08308)
*入选：RL×LLM方法*

> 📄 **摘要**：Reward machines (RMs) have been proposed as a reward formulation in reinforcement learning (RL) to capture non-Markovian tasks where credit assignment depends on history. By representing reward functions as automata, RMs expose the task's temporal structure and allow such rewards to be handled within a Markovian framework. However, they assume a labelling function, a proposition-grounding oracle for observations, which must be manually engineered for each environment, limiting their wider applicability. In this work, we address this limitation by proposing RM-VLM, a novel approach in which a large language model (LLM) generates an RM from a natural-language task description, and a vision-language model (VLM) acts as the labelling function, grounding the RM's propositions over image-based observations during RM-guided policy learning. A VLM-based value function estimator is used to assess the agent's progress towards each RM transition and derive a dense reward signal. We evaluate RM-VLM on three domains covering non-Markovian grid-world navigation, robotic manipulation, and 3D object collection. Our experimental results show that RM-VLM consistently achieves higher task success rates than existing VLM-based reward methods across all tested domains.

**一句话**：用 LLM 从自然语言任务描述生成 reward machine（自动机形式的结构化任务表示），再由 VLM 充当 labelling function，把自动机中的命题 grounding 到图像观测上，用于 RM 引导的 RL 策略学习。

痛点：reward machine 能刻画非马尔可夫任务的时间结构，但需要人工为每个环境设计 labelling function（命题落地 oracle），难以推广。方法：让 LLM 从自然语言任务描述生成 RM 自动机，VLM 在图像观测上把 RM 的命题落地为真值，并用基于 VLM 的价值函数估计到各次转移的进度，从而得到稠密奖励。结果：在网格导航、机器人操作、3D 物体采集三个域上，任务成功率一致高于现有 VLM-based reward 方法。

> 🔗 **与课题**：主要支撑环节②（Workflow→结构化表示）：LLM 直接产出带状态与转移依赖的自动机，相当于把自然语言任务编译成依赖闭合的图结构（states + transitions 与 processes + links 同构）。次要支撑环节④的弱类比：VLM 作为 labelling function 把抽象命题绑定到可观测/可判定的具体实体，思想上接近 operator grounding 中的“符号→可执行/可判定落地”，但落地对象是感知命题而非 GIS 算子。环节③（能力迁移）与⑥（训练）基本不涉及：LLM 只做一次性生成、未被训练，也没有跨域/跨平台迁移的实证。因此归入 5-7 档的通用结构化生成方法，而非核心 8-10 档。

💡 **启发**：可借用其“结构生成 + 逐命题落地校验 + 按转移进度给稠密反馈”的三段式：把生成的 QGIS processes+links 图逐节点/逐 link 用可执行性或算子存在性做落地校验，并用“到下一次转移的进度”类比工作流步骤完成度，作为中间过程评测信号。

⚠️ **局限**：命题词表与自动机正确性未被系统验证，实验限于小规模 gridworld/机器人域，且 grounding 是感知层符号绑定而非工具/API 算子落地，与本研究目标存在语义差距。

### ⭐⭐ AiXapply: Fast and Reliable Full-File Code Integration with Specialized Small Models for IDE Workflows
**5/10** · Siyuan Jiang、Xiang Cai、Peixu Wang、Yu Han、Yihong Dong、Wei Ning · arXiv (Cornell University) · 2026-11-05 · [原文](https://doi.org/10.48550/arxiv.2611.07634)
*入选：RL×LLM方法*

> 📄 **摘要**：Large language models increasingly assist developers by proposing small code edits, yet reliably integrating a partial update snippet into an existing file while preserving unrelated content remains poorly supported by current code-generation workflows. We formalize the Code Integration (Apply) task as follows: given an original file and an update snippet, the system must produce the complete merged file while preserving all content outside the requested edit. We construct a high-quality multi-language dataset from real commits via a structured pipeline that converts code changes into update snippets paired with full-file ground truth and enforces consistency through verification and filtering. We then train a specialized 4B model, aiXapply, using supervised fine-tuning and reinforcement learning (GRPO). The supervised variant achieves 94.4% accuracy under our language-aware comparison, surpassing a strong large-model (Deepseek-V3.2) baseline (91.6%). Speculative decoding enables aiXapply-RL to reach $\sim$2700 tokens/s on a single A100 in a decoding subset; on the full benchmark, it achieves roughly 75$\times$ lower latency than the API-served Deepseek-V3.2 baseline. We further conduct an industrial deployment of aiXapply-RL in the aiXcoder IDE plugin as a dedicated Apply service, reducing mean Apply latency from 50 seconds to 1.89 seconds by offloading full-file generation from the upstream large model. Under time-based capacity planning, replacing one of five upstream serving instances would save 20% of upstream machine cost before the additional shared A100 service cost. Overall, our results demonstrate that treating code integration as a standalone task enables small models to achieve high accuracy, practical efficiency, and concrete industrial benefits in real-world IDE workflows where latency, cost and privacy are critical.

**一句话**：论文形式化了“Code Integration (Apply)”任务（把局部更新片段合入原文件并保持其余内容不变），用真实 commit 构建多语言数据集，训练专用 4B 模型 aiXapply（SFT 与 GRPO），并部署到 IDE 插件中做低延迟 Apply 服务。

痛点：LLM 生成小片段代码容易，但把片段可靠合入现有文件、完整保留无关内容，现有代码生成流程支持很差。方法：将 Apply 定义为原文件+更新片段→完整合并文件的生成任务，用结构化流水线从真实 commit 构造带全文件真值的数据集并做一致性校验过滤，再用 SFT 与 GRPO 训练专用 4B 模型，配合投机解码降延迟。结果：SFT 版本在语言感知比较下达 94.4% 准确率（超 Deepseek-V3.2 的 91.6%），RL 版单 A100 约 2700 tokens/s，全基准延迟约为 API 大模型的 1/75，IDE 插件中平均 Apply 延迟从 50s 降到 1.89s。

> 🔗 **与课题**：主要支撑环节⑥（训练/后训练）：给出“真实数据构造流水线 + SFT + GRPO + 专用小模型 + 低延迟部署”的完整范式，可作为把工作流推理能力固化进小模型的候选手段；其次弱相关于⑤（结构化生成）：其核心约束是“局部改写、全局保真”，与生成依赖闭合、结构完整的 QGIS processes+links 图在“部分修改 vs 整体一致性”的问题形态上同构（可类比为对已有工作流图做算子级增量编辑并保持依赖闭合）。但与①②③④⑦基本无关：不涉及任务分解/流程规划、不涉及跨域跨平台能力迁移（无源域→目标域实证）、不做工具/算子 grounding、也没有工作流推理质量或迁移保持率类评测。

💡 **启发**：可借鉴其“从真实 commit 反向构造 (原文件, 更新片段, 全文件真值)”的数据构造与一致性校验过滤思路，迁移为“从真实 QGIS 工程历史版本构造 (旧工作流图, 局部编辑意图, 新图真值)”的增量图编辑训练数据；以及用投机解码/专用小模型把 grounding 阶段的生成延迟压到可交互水平。

⚠️ **局限**：任务是单文件文本合并，与需要跨步骤依赖推理和图结构生成的 workflow grounding 差距较大，且未涉及能力迁移与算子合法性（幻觉算子）评测，引用时只能作为训练与部署工程范式而非认知迁移证据。
