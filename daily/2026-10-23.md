### 🔥 ⭐⭐⭐⭐ Training Small Language Models for Transferable Tool Selection
**8/10** · Zhaoyi Zhou、Akshayaa Magesh、Jeongyeol Kwon、Artem Kuriksha、Daniel Jiang、Andrea Zanette · arXiv · 2026-10-22 · [原文](https://arxiv.org/abs/2610.31483v1) · [PDF](https://arxiv.org/pdf/2610.31483v1)
*入选：能力迁移*

> 📄 **摘要**：As LLM agents operate over corpora of more than ten thousand tools, selecting the right tool for a complex multi-step user instruction becomes a central bottleneck. Tool descriptions cannot all fit in context, and relevance-based retrievers only rank tools without knowing which are actually needed. Recent work instead leverages proprietary commercial LLMs like Claude or ChatGPT to drive a retriever, decomposing the instruction and selecting over retrieved candidates. We show that a small, open model can be trained via reinforcement learning to perform the same functionality. On ToolBench, a Qwen3-8B model post-trained with our recipe outperforms Llama-4-Maverick (402B). In addition, the trained model transfers directly to different retrievers and generalizes to new tool corpora in different domains.

**一句话**：该工作用强化学习后训练 Qwen3-8B 这类小模型，在万级工具库上完成复杂多步指令的工具分解与选择，并验证其能迁移到不同检索器和不同领域的新工具库。

痛点：当工具库规模达到上万时，工具描述无法全部放入上下文，基于相关性的检索器只会排序、不知道真正需要哪些工具，而现有做法依赖 Claude/ChatGPT 等闭源大模型驱动检索与选择。方法：用 RL 后训练一个小型开源模型，使其学会分解指令并在检索候选中做工具选择。结果：在 ToolBench 上，Qwen3-8B 超过 402B 的 Llama-4-Maverick，且训练所得能力可直接迁移到不同检索器并泛化到不同领域的新工具语料。

> 🔗 **与课题**：该文直接支撑第③环节（能力迁移）：它实证研究了 LLM 上「源工具语料→目标工具语料」「源检索器→目标检索器」的能力保持与泛化，正是我们 GEE→QGIS 跨平台迁移所需的同构问题（tool→tool、domain→domain transfer），可用来界定「transfer retention」这一指标。它同时支撑第①环节：模型需先对多步用户指令做分解，再逐子目标选工具，属于任务分解和流程规划层面的工作流推理。也支撑第④环节的邻近形态：工具选择即「指令→operator 候选」的 grounding 前端，其检索-候选-选择链路可平移到 QGIS operator grounding 的候选筛选阶段。第⑥环节：RL 后训练被明确绑定在 tool 选择场景（非纯 RL 算法改进），符合我们「RL 仅在绑定 tool/code/workflow 时算高相关」的口径，是小模型习得可迁移工具知识的训练手段候选。第⑦环节：它给出了跨检索器、跨工具库的迁移评测协议与准确率对比范式，可借鉴为我们「迁移保持率」的评测设计。

💡 **启发**：可直接借用其「同一模型换检索器/换工具库再测」的迁移保持率评测协议，作为我们 GEE→QGIS 迁移实验的对照范式；另外「用 RL 让小模型内化指令分解+候选选择」的训练配方，可作为把 workflow reasoning 蒸馏进小模型的候选手段，并与 DAPT/SFT 做对比。

⚠️ **局限**：它只做单步工具选择（从检索候选中选工具），不生成带依赖的 processes+links 图结构，也不涉及算子参数落地与执行成功率，且评测限于 ToolBench 类选择准确率，未验证下游可执行性。

🚨 **为什么必须重视**：该文与我们的核心科学问题在第③环节上直接重合：它正是「小模型习得的工具选择能力能否迁移到新工具库/新检索器」的实证研究，若不引用，我们的 GEE→QGIS 迁移主张会被认为缺少最近邻竞品对照。并且它提供了可立即复用的迁移保持率评测协议与 RL 训练配方，能在方法章节直接作为对照实验与基线设计参照。

### 🔥 ⭐⭐⭐⭐ Once a Tree, Always a Tree? Cross-lingual Transfer of Hierarchical Generalization in Language Models
**8/10** · Shin Yamaguchi、Masaya Taniguchi、Tatsuki Kuribayashi、Taro Watanabe、Yoshinobu Kano · arXiv · 2026-10-22 · [原文](https://arxiv.org/abs/2610.30960v1) · [PDF](https://arxiv.org/pdf/2610.30960v1)
*入选：能力迁移*

> 📄 **摘要**：Language models (LMs) often exhibit successful cross-lingual transfer through continued (pre)training, still their underlying process remains unclear. One possibility is that LMs can leverage the evidence toward language-universal principles, namely, hierarchical structure, from a source language (L1) to a new language (L2), while many other non-linguistic explanations, e.g., improved initialization of position embeddings, can be potentially possible. In this study, to quantify the cross-linguistic transferability of linguistic evidence in cross-lingual LM training, we introduce a new experimental design, namely, a cross-lingual poverty-of-stimulus (CPOS) setting that ablates how LMs' hierarchical generalization in L2 can be led by structural evidence provided in L1. We contrast counterfactual L1 and L2 learning scenarios where the L2 corpus is ambiguous between linear and hierarchical grammar rules, while the amount of positive evidence for the hierarchical rule is controlled on the L1 side. Our experimental results show that LMs can partially, yet not perfectly, transfer L1 structural evidence to L2, yielding only a small but detectable hierarchical bias, while the strength of transfer depends on language pairs. We further ablate the conditions for successful transfer, motivated by recent reports on the substantial impact of vocabulary overlap. We indeed find that vocabulary overlap is crucial even for the cross-lingual transfer of hierarchical syntactic generalization. This suggests that this also explains the language-pair-dependent tendencies in the main experiments and suggests that the transfer of linguistic evidence in continued new-language learning is only conditionally achievable.

**一句话**：该文提出跨语言 poverty-of-stimulus（CPOS）实验范式，通过控制 L1 中层级语法规则的正例证据量，量化 L2 训练中层级泛化能力的迁移程度。

痛点是：跨语言（持续）预训练为何有效尚不清楚，是模型真的迁移了'层级结构'这类语言普遍原则，还是仅仅因为位置嵌入初始化变好等非语言学因素。作者设计了 cross-lingual POS 反事实实验：L2 语料在线性与层级语法规则之间保持歧义，只在 L1 侧操纵层级规则的正例证据量，从而检验 L1 结构证据能否诱发 L2 的层级泛化。结果显示迁移是部分的而非完全的，只产生小但可检测的 hierarchical bias，且强度依赖语言对；进一步消融发现，词表重叠（vocabulary overlap）对层级句法泛化的跨语言迁移也是关键条件。

> 🔗 **与课题**：该文直接支撑环节③（能力迁移：源域→目标域），并在方法论上补充环节⑦（迁移保持率评测）。它把'模型能否把源域学到的抽象结构知识迁移到目标域'这一研究问题，用受控的反事实数据设计做了实证，与'GEE 上习得的 workflow 推理能力能否迁移到 QGIS operator grounding'属于同构问题：源域学的是结构/规则（层级语法对应 workflow 依赖结构），目标域的表现需要在表层形式变化下仍保持。更关键的是，它给出可迁移性的两个判据：迁移是部分的（partial transfer，不是全有或全无），这对我们'迁移保持率'指标的设定有直接校准意义；以及词表/表层重叠是迁移成功的必要条件，这直接对应我们的假设——GEE 与 QGIS 之间算子词汇与概念命名的重叠度，可能是决定 workflow 知识能否落地到 QGIS operator 的关键变量，可作为一个显式可控的自变量。其 CPOS 消融思路（目标域歧义、源域控制证据量）也可改造为'目标域平台歧义、源域控制 workflow 证据量'的迁移归因实验。局限在于它完全在句法/语言学语境中，不涉及 tool、code 或 operator grounding，因此它提供的是迁移机制的通用证据与实验协议，而非 QGIS 落地方法本身。

💡 **启发**：可直接借鉴其'源域控制证据量 + 目标域保持歧义'的反事实消融设计，做 GEE→QGIS 的迁移归因实验（控制 GEE workflow 数据量，测 QGIS grounding 的依赖闭合率）；并把'词汇/算子命名重叠度'当作显式自变量来测迁移保持率。

⚠️ **局限**：研究对象是合成/受控的句法层级规则，规模小且与工具调用、代码生成无关，迁移结论只能作为机制类比，不能直接外推到 QGIS 算子落地。

🚨 **为什么必须重视**：它与本课题的核心科学问题同构：抽象结构知识能否在表层形式改变后跨域保持；这是少数给出'部分迁移 + 重叠度是必要条件'这类可操作结论的受控实证，可直接影响我们对迁移保持率的预期设定与实验设计。其 CPOS 范式可低成本移植为 GEE→QGIS 迁移归因实验，若不引用就可能重复造轮子或误设指标。

### ⭐⭐⭐⭐ Learning Robot Behavior Priors from Non-Robotic Synthetic Data
**7/10** · Mateusz Odrowaz-Sypniewski、Michael Amir、Jasmine Bayrooti、Ajay Shankar、Amanda Prorok · arXiv · 2026-10-22 · [原文](https://arxiv.org/abs/2610.31275v1) · [PDF](https://arxiv.org/pdf/2610.31275v1)
*入选：能力迁移*

> 📄 **摘要**：Real robot data, rich across tasks and morphologies, is often treated as the bottleneck for training robot learning models, including embodied foundation models that aim for zero-shot physical transfer. In this paper, we investigate the degree to which such models can acquire necessary structure using data from systems without embodiment. To this end, we test if inexpensive, procedurally generated synthetic data can yield useful priors before a model observes any real-world behavior. We study this through robot action prediction, a natural pretraining objective and a direct test of whether structure learned from arbitrary synthetic tasks transfers to embodied settings. We introduce three data generation pipelines that model mathematical abstractions of robotic control, and use them as pretraining priors for a Transformer. We demonstrate that a model trained purely on this non-robotic data attains non-trivial zero-shot prediction performance on unseen physical robot tasks via an in-context learning mechanism, and that our specialized control priors notably improve upon generic causal priors. We also compare against a compute-matched baseline trained on real robot data, and find that it outperforms our model but only on the datasets it was trained on. These findings suggest that procedurally generated, mathematical abstractions can yield useful robotic priors, offering a potential complement to expensive embodied data collection.

**一句话**：论文使用程序化生成的“非具身”合成数据（机器人控制的数学抽象）预训练 Transformer，检验这些数据能否在真实机器人动作预测上实现零样本迁移。

痛点：真实机器人数据昂贵且稀缺，被视作具身基础模型训练的主要瓶颈。方法：论文设计三条合成数据生成管线来建模机器人控制的数学抽象，并将它们作为预训练先验；然后通过上下文学习做零样本动作预测，同时与等算力的真实数据基线和通用因果先验进行对比。结果：只用非机器人数据预训练的模型在未见真实任务上取得了非平凡的零样本表现，而且专用控制先验显著优于通用因果先验；真实数据基线在训练过的数据集上更强，但在未见任务上并不占优。

> 🔗 **与课题**：支撑③⑥⑦。③：本文是源域（非具身的程序化合成抽象）→目标域（真实具身任务）的先验迁移实证，并设置了“专用先验 vs 通用因果先验”的对照，这与“GEE 专用工作流训练 vs 通用代码/推理训练能否迁移到 QGIS 算子落地”高度同构；④⑤不涉及。⑥：预训练数据构成就是先验来源，提示 DAPT/SFT 阶段的语料选择（领域专用 vs 通用）本身是迁移能力的自变量，而非固定的实现细节。⑦：等算力匹配基线 + “仅在训练分布上更优”的结论，正是 transfer retention 的度量范式，能区分“域内熟练度”与“跨域保持率”。但迁移对象是低层动作/控制先验，不涉及任务分解、依赖/DAG 结构或算子 grounding，故为方法论级支撑而非核心撞车。

💡 **启发**：可借鉴其三方对照设计（专用先验 / 通用先验 / 等算力域内基线），用于验证“GEE 工作流专精训练”是否比“通用代码或推理训练”带来更高的 QGIS 落地迁移保持率；并用上下文学习探针（零示例/少示例）检验工作流知识是内化为可激活先验还是表层记忆。

⚠️ **局限**：迁移对象是低层控制/动作预测先验，输出为连续回归而非符号化图结构，缺少对结构化输出正确性（依赖闭合、幻觉算子）的评测，跨到高层工作流推理需额外论证。

### ⭐⭐⭐⭐ Same Beliefs, Different Policies: Learning Reusable Representations for Early Stopping in LLM Reasoning
**7/10** · Jingwei Ni、Dmitry Abulkhanov、Vladislav Smirnov、Markus Leippold、Elliott Ash、Timothy Baldwin · arXiv · 2026-10-21 · [原文](https://arxiv.org/abs/2610.30450v1) · [PDF](https://arxiv.org/pdf/2610.30450v1)
*入选：能力迁移*

> 📄 **摘要**：Reasoning LLMs often continue reasoning after reaching a correct answer, wasting computation and sometimes replacing it with an incorrect one. Deciding when to stop is a metareasoning problem: the model must weigh what further reasoning could achieve against its cost, given what it can already answer. Direct utility training learns a stopping representation at a chosen token price; supporting new prices can require additional controller training. We introduce BELT (BELief-based Termination), which separates outcome prediction from stopping control. It learns beliefs about current and future answers from a frozen LLM's hidden states, then fits a linear stopping policy on the frozen features. The prediction targets are independent of token price, so one probe supports different accuracy-cost trade-offs through CPU policy refitting or threshold adjustment. Averaged over five out-of-distribution (OOD) math benchmarks, BELT reduces generated tokens by 41% on Qwen3-1.7B and 51% on OLMo-3-7B-Think without loss of accuracy. The same math-trained BELT transfers to coding and agentic tasks without training on code or agentic data. In all three domains, its accuracy-cost trade-offs are competitive with or better than those of end-to-end controllers. On OLMo3, its probe has 21.2x fewer parameters than one checkpoint of the strongest baseline, OS-Pruner, and needs 55x fewer training GPU-hours than OS-Pruner's five price-specific checkpoints.

**一句话**：提出 BELT：在冻结的 LLM 隐状态上学习关于当前答案和未来答案正确性的信念探针，再用线性策略头决定何时停止推理，实现一次训练支持多种精度-成本权衡，并可跨域迁移。

痛点：推理型 LLM 常在已经得到正确答案后继续推理，浪费算力甚至把正确答案改错；而按固定 token 价格直接训练停止控制器时，换一个价格就要重训控制器。方法：把“结果预测”与“停止控制”解耦——从冻结模型的隐状态中学习与 token 价格无关的信念表征，再在冻结特征上拟合线性停止策略，通过 CPU 重拟合或调整阈值即可切换不同的精度-成本权衡。结果：在五个分布外（OOD）数学基准上平均减少 41%（Qwen3-1.7B）和 51%（OLMo-3-7B-Think）的生成 token，且无精度损失；数学上训练出的 BELT 还能零样本迁移到代码与 agentic 任务，表现优于端到端控制器，参数量和训练 GPU 小时数均大幅更低。

> 🔗 **与课题**：主要支撑环节③（跨域能力/表征迁移）与⑥（轻量训练/适配）、⑦（评测协议）。它提供了一个“冻结主干→隐状态探针→廉价策略头→多档部署”的可复用表征迁移范式：源域（数学）训练出的表征无需目标域数据即可迁移到代码/agentic，并保持权衡竞争力，这正是我们“迁移保持率（transfer retention）”需要量化的现象。⑦上其 accuracy-cost 曲线与 OOD 基准报告方式，可直接改写为“GEE→QGIS 迁移保持率”的度量模板。⑥上“价格无关目标 + 冻结特征 + CPU 重拟合”说明适配层可以做到极轻量，对 DAPT/SFT 之外的轻量迁移路线是有力佐证。但它迁移的是元推理（何时停止）的信号，而非任务分解/步骤规划的工作流知识，因此不直接支撑①GIS Task→Workflow、②结构化表示、④QGIS operator grounding、⑤processes+links 图生成。

💡 **启发**：可借“价格无关目标 + 冻结特征 + CPU 重拟合线性头”的思路：把工作流知识表征与具体输出格式/算子集解耦，使一次训练即可通过重拟合在多档落地配置（GEE 风格 vs QGIS 算子集）间切换，并用 OOD 迁移保持率作核心指标。其“信念探针预测当前/未来答案正确性”可类比为“当前子目标是否已可闭合”的可执行性预测器，用于 QGIS 图生成时的依赖闭合自检与提前终止。

⚠️ **局限**：迁移对象仅是停止策略这一元推理信号，不涉及任务级能力或工具/算子落地，且实验限于数学、代码、agentic 基准，未评估结构化输出的语法合法性与执行成功率。

### ⭐⭐⭐ Exploiting the Model-Context Protocol for Earth Observation Data Access and Workflow Orchestration
**6/10** · Claudio Pisa、Mohanad Albughdadi、Marica Antonacci、Vasileios Baousis、F. Fornari、Tolga Kaprol · 预印本 · 2026-10-21 · [原文](https://doi.org/10.22323/1.523.0003)
*入选：领域×任务*

> 📄 **摘要**：The EO4EU project democratises access to Earth Observation (EO) data by providing a comprehensive platform for a wide spectrum of stakeholders, from researchers to policymakers. The platform facilitates the retrieval of EO data and the orchestration of complex computational and machine learning workflows. To this end, it features a semantic knowledge graph to enhance EO metadata discoverability, supports data fusion across heterogeneous sources, and enables advanced visualisation, including immersive VR/XR environments. The Model Context Protocol (MCP) is a lightweight, standards-based protocol built on JSON-RPC that supports the dynamic coupling of Large Language Models (LLMs) with external data and services. MCP introduces a set of abstractions tailored to the operational logic of LLMs, namely tools, resources, and prompts, enabling the integration of existing platforms with LLMs regardless of their accessibility model. As part of the EO4EU project, we have developed a prototype MCP server that encapsulates the EO4EU REST APIs into MCP-compliant tools. Each tool performs a goal-oriented operation, such as data discovery or workflow management, exposing an LLM-interpretable and actionable description to MCP clients. Lessons learned include the importance of managing the LLM context window: verbose API responses can quickly exhaust it, but the MCP server can mitigate this by filtering out irrelevant information and by mapping each MCP tool to multiple API endpoints.
