痛点是企业工作流编排需要把非结构化指令转为可执行依赖图并动态分派/重规划，现有方法多依赖表层启发式或缺乏失败反馈闭环。方法上 LLM 生成有序子任务及优先级结构，学习式依赖打分器按子任务语义重写边，三关系异构图（任务-员工-技能）配类型感知注意力做路由，独立 PPO actor + 集中式 critic 训练并注入语义先验。结果通过基于日志回放的 duration/failure 模型评测，验证分解、路由与在线重规划的联合有效性。

> 🔗 **与课题**：主要支撑环节①（GIS Task→Workflow）：LLM 从自然语言指令生成有序子任务列表与 precedence 结构，是典型的任务分解/工作流推理；同时支撑②（Workflow→结构化表示）：用学习式依赖打分器按语义重写边，而非表层启发式，直接对应依赖闭合的结构化图生成。附带触及⑦（评测）：用日志回放拟合 duration/failure 模型构建可复现评测环境。与③能力迁移、④QGIS operator grounding、⑤processes+links 具体图结构无直接关系，属于跨平台迁移的通用上游方法（工作流推理与依赖结构生成）。

💡 **启发**：可借鉴两点：一是用“可学习依赖打分器”按子任务语义重写依赖边，替代规则式/顺序式连线，可用于提升 QGIS processes+links 的依赖闭合率；二是失败信号只触发失败子图的定向重分解而不重算已完成子任务，可作为 workflow 级增量重规划的评测设计模板。

### ⭐⭐ MAESTRO: Fine-Tuned Multiagent Large Action Model-Based GenAI Assistant Integrating IoT Sensing, Smart Control, and Extended Reality for Human-Building Interaction
**5/10** · Oscar Poudel、Rayan H. Assaad、Andrew B. Park、Mohamad Awada · Journal of Computing in Civil Engineering · 2026-09-30 · [原文](https://doi.org/10.1061/jccee5.cpeng-7915)

> 📄 **摘要**：Abstract There has been recent interest in smart human–building interaction (HBI) interfaces to improve how occupants interact with building systems. Intelligent facility management (FM) utilizes HBI principles to transform static infrastructures into dynamic, human-centric environments, where facility managers need to interpret live Internet-of-things (IoT) sensor data, consult procedures, and execute safe control actions for various building systems. These tasks are fragmented across dashboards, manuals, and control panels, increasing cognitive load and slowing down decision-making. To address these challenges, this study proposes the multiagent extended-reality and sensing-aware task-level reasoning orchestrator (MAESTRO). MAESTRO is a multimodal agentic GenAI assistant comprised of four agents that support procedural queries, telemetry interpretation, and supervised device actuation in a single HBI loop. MAESTRO integrates a large action model (LAM)-based system with retrieval-augmented reasoning interfaced in an extended reality (XR) environment and mediated by a Model Context Protocol. It uses an orchestrator, which is the coordination component that interprets each user request and decides which agent capability should handle the request, while enforcing supervised and schema validated execution for sensing and actuation. The orchestrator routes each request to the appropriate agents including a domain-adapted FM language agent trained on manuals, logs, and work orders; an IoT control agent that generates schema validated tool calls to sensors and actuators; and a vision language agent for image-based queries.
