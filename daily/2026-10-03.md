### 🔥 ⭐⭐⭐⭐ Cross-Lingual Alignment for Decoder-Only Models using MoE Routers
**8/10** · Lucas Bandarkar、Clark Peng、Ahmed Haj Ahmed、Aditi Khandelwal、Nanyun Peng · arXiv · 2026-10-01 · [原文](https://arxiv.org/abs/2610.01921v1) · [PDF](https://arxiv.org/pdf/2610.01921v1)
*入选：能力迁移*

> 📄 **摘要**：Cross-lingual contrastive learning has been a core component of multilingual encoder training, but the ability to explicitly align representations is not possible in decoder-only LLMs because of varying multilingual tokenization. However, a growing amount of research suggests that even in LLMs, higher cross-lingual representational alignment leads to improved cross-lingual transfer. In this paper, we propose a novel approach to reimagine cross-lingual contrastive learning given the architectural constraints of modern LLMs. Rather than applying an auxiliary alignment loss on hidden states, we propose using the outputs of the mixture-of-experts (MoE) routers as the target for alignment. Router outputs lend themselves better to pooling over many tokens, enabling more reliable cross-lingual comparisons at the sequence-level. Controlled continual pre-training experiments on four open-source MoEs show that incorporating this routing loss also aligns the underlying hidden representations across languages. Most importantly, this loss improves multilingual performance on our diverse evaluation suite, demonstrating the potential of cross-lingual MoE router alignment.

**一句话**：提出用 MoE 路由器输出作为跨语言对齐目标，通过持续预训练提升解码器模型的多语言迁移性能。

针对解码器 LLM 因分词差异难以显式对齐跨语言表示的问题，提出将 MoE 路由器输出作为序列级对齐目标，并在四个开源 MoE 模型上进行受控持续预训练。结果表明该路由损失能隐式对齐隐藏表示，并在多语言评测套件上提升性能，展示了跨语言 MoE 路由器对齐的潜力。

> 🔗 **与课题**：③ 能力迁移：论文直接研究 LLM 的跨语言能力迁移，通过 MoE 路由器对齐实现源语言到目标语言的知识迁移，属于“源域→目标域”的迁移实证研究；其方法可类比用于 GEE→QGIS 的工作流知识迁移，即对齐不同平台下的内部路由表示以提升迁移保持率。⑥ 训练/后训练：采用受控持续预训练（continual pre-training）在四个开源 MoE 上验证，属于 DAPT 类训练手段；路由损失可作为训练目标注入，为在 GIS 工作流数据上继续预训练以增强可迁移性提供参考。⑦ 评测：在多语言评测套件上验证迁移提升，其评测协议关注迁移后的性能保持，可借鉴用于设计工作流推理的迁移保持率（transfer retention）指标。② 结构化表示：不直接涉及工作流的结构化/DAG 生成。④⑤ grounding/结构化图生成：未涉及工具算子落地或 QGIS 图生成。① 工作流推理：未涉及任务分解或流程规划。

💡 **启发**：可借鉴其用 MoE 路由器输出作为对齐目标的做法，在 GEE 和 QGIS 工作流数据上对齐模型内部路由表示，以增强跨平台迁移；序列级池化比较的思路也可用于比较不同平台下生成的工作流图结构。

⚠️ **局限**：研究限于跨语言迁移，未验证在工具/算子接地或结构化工作流生成任务上的有效性，且依赖 MoE 架构。

🚨 **为什么必须重视**：该论文直接研究 LLM 的能力迁移（③），与课题的核心科学问题中‘能力迁移’环节高度重合；其提出的路由器对齐损失提供了一种新的迁移训练手段，可立即尝试用于 GEE→QGIS 的跨平台工作流知识迁移；持续预训练的实验设置也为我们的训练阶段提供了可复现的协议参考。

### 🔥 ⭐⭐⭐⭐ Cross-Benchmark Transfer from RL on Agentic Coding Tasks
**8/10** · Sushant Mehta、Logan Ritchie、Edwin Chen · arXiv · 2026-10-01 · [原文](https://arxiv.org/abs/2610.00890v1) · [PDF](https://arxiv.org/pdf/2610.00890v1)
*入选：RL×LLM方法*

> 📄 **摘要**：Coding agents often fail in the last mile: they build most of a feature but drop a requirement, test only the cases their implementation already handles, break behavior that was supposed to stay intact, or validate against an unchecked assumption. We ask whether reinforcement learning (RL) on expert-built agentic coding tasks closes this gap, and whether what the agent learns transfers beyond the training distribution. We post-train Kimi K2.7 Code, a 1T-parameter (32B active) open-weight mixture-of-experts model, with RL alone on 1,700 tasks: 1,000 repository tasks graded by hidden fail-to-pass tests and by pass-to-pass tests of existing behavior, and 700 terminal tasks graded by expert-written hidden verifiers. The reward is the fraction of target checks passed and drops to zero if any pass-to-pass test fails. One epoch of GSPO on a rank-32 LoRA adapter improves pass@1 on each of the six external benchmarks we evaluated, across three agent harnesses: SWE-Bench Pro (60.1 to 64.8), DeepSWE (31.0 to 43.4), Terminal-Bench 2.1 (67.4 to 82.0), Terminal-Bench 3 (1.4 to 12.1), Terminal-Bench 4 (0.0 to 7.6), and SWE-Marathon (5.0 to 25.0). Pooled over the five independent task sets (Terminal-Bench 4 revises Terminal-Bench 3), the improvement is significant (p < 0.001), and it remains significant on the three sets released after the training data was collected (p = 0.004); the model also improves under both harnesses never used in training. Median trajectories on DeepSWE and Terminal-Bench 3 are 24-35% shorter in agent steps. The base model's failed DeepSWE runs are mostly near-misses, and on the tasks the trained model newly solves, paired trajectories show it avoiding each of the four failure modes above.

**一句话**：在 1700 条专家构建的 agentic coding 任务上仅用 RL（GSPO + rank-32 LoRA）后训练 Kimi K2.7 Code，验证其在六个外部基准、三种 agent harness 上的跨分布迁移提升。

痛点：编码 agent 常在"最后一公里"失败——漏掉需求、只测自己已实现的用例、破坏原有行为、依赖未经验证的假设。方法：用 1000 个仓库任务（隐藏 fail-to-pass 测试 + 保护既有行为的 pass-to-pass 测试）和 700 个终端任务（专家隐藏验证器）做 RL，奖励为目标检查通过率，任一 pass-to-pass 失败即归零；单 epoch GSPO 训 rank-32 LoRA。结果：六个外部基准上 pass@1 全面提升（如 SWE-Bench Pro 60.1→64.8、Terminal-Bench 2.1 67.4→82.0、SWE-Marathon 5.0→25.0），跨五个任务集 p<0.001，且在训练数据收集之后才发布的三个集上仍显著（p=0.004），在训练中从未使用过的两个 harness 下也有增益。

> 🔗 **与课题**：主要支撑③能力迁移：论文的核心科学问题就是"在源域（自建 agentic coding 任务分布）上通过 RL 学到的能力能否迁移到目标域（未见的六个外部基准、未见 harness）"，与课题中"GEE workflow 上习得的工作流推理能力能否迁移到 QGIS operator grounding"在实验范式上同构，其"训练集之外发布的新基准 + 未见 harness"的双重 held-out 设计可直接改写为"未见的 QGIS 工具链/未见算子集"迁移评测。其次支撑⑥训练/后训练：给出 RL-only（GSPO + LoRA，单 epoch）作为迁移手段的完整配方与超参规模，可作为 DAPT/SFT 之外的候选解释框架。再次支撑⑦评测：fail-to-pass + pass-to-pass 的混合奖励与"任何回归即零分"的硬约束，正是我们关心的"依赖闭合/不破坏既有结构"的指标原型，可类比为 QGIS 图生成中的依赖闭合率与幻觉算子惩罚。另外间接支撑②结构化表示与④grounding：仓库级任务要求 agent 在多文件、多步骤依赖中完成并保持既有行为，本质上考察了步骤规划与依赖组织的正确性，这与 processes+links 图结构必须依赖闭合、可执行的要求同源。整体上它在"能力迁移 + 训练手段 + 评测协议"三条线上同时提供可借用证据，唯一缺口是评测对象为代码/终端 harness 而非 GIS 算子，因此判 8 而非 10。

💡 **启发**：可直接借用其"pass-to-pass 回归即归零"的奖励构造，把 QGIS 生成评测改为"目标算子覆盖率 + 既有依赖边不可破坏"的复合奖励；并借其"训练后新发布的基准 + 未见 harness"双 held-out 设计，构造"训练时未见的 QGIS 算子/插件"迁移测试集。

⚠️ **局限**：仅在单一开源 MoE 模型上做一次单 epoch RL，未与 SFT/DAPT 基线严格对照，也未能解释迁移收益究竟来自工作流推理还是通用代码能力；且迁移目标仍是文本/终端任务，跨模态、跨工具平台的外推性未验证。

🚨 **为什么必须重视**：它与课题的核心科学问题正面撞车：同样是"在源任务分布上后训练，考察能力向未见目标域的迁移保持率"，且已经用"训练后新发布基准 + 未见 harness"给出了 p<0.001 的迁移证据，属于必须立即纳入的竞品/同类动向。其 pass-to-pass 零容忍奖励与多 harness 迁移协议可几乎原样移植到 GEE→QGIS 的迁移保持率实验上，若我们不引用、不对比，迁移评测协议会明显弱于该工作。

### 🔥 ⭐⭐⭐⭐ From Given to Gathered Evidence: Agentic Learning for Longitudinal Medical Reasoning
**8/10** · Minye Shao、Chaohui Yu、Yixuan Wu、Fan Wang、Ling Shao、Yang Long · arXiv (Cornell University) · 2026-09-30 · [原文](https://doi.org/10.48550/arxiv.2609.39566)
*入选：能力迁移*

> 📄 **摘要**：Foundation models can serve as clinical agents through tool-use harnesses. However, conventional medical benchmarks assess reasoning over preselected evidence rather than the ability to seek it across clinical records and longitudinal imaging. We propose CASE: a series of role-specific Clinical Agents for Seeking Evidence, together with a tool-use harness and an agentic post-training framework for compact vision-language policy models. We further introduce a longitudinal multimodal benchmark built on UK Biobank, comprising 50,401 clinical questions derived from real-world ICD-10-coded diagnoses of 4,739 participants. Each question links to a patient-specific environment containing clinical context and multi-sequence MRI from baseline and follow-up visits, where agents autonomously select which visits, organs, modalities, slices, and specialist tools to inspect and compare. Supervised fine-tuning transfers evidence-seeking workflows from 14,734 frontier-model interaction trajectories, followed by agentic reinforcement learning on the learner's own environment interactions. Privileged on-policy self-distillation and rubric-based LLM feedback refine evidence-to-conclusion reasoning without prescribing tool sequences. Experiments show that CASE moves beyond question-answer imitation toward transferable investigation policies, strengthening evidence-grounded longitudinal reasoning. Under matched evaluation conditions, our Qwen3-VL-8B based agent achieves over 16% and 10% relative improvements in answer accuracy over GPT-5.4 and Claude Opus 4.8. Code will be available at https://github.com/VinyehShaw/CASE.

**一句话**：提出CASE——一组角色化临床证据检索智能体，配合工具使用harness与智能体后训练框架，在UK Biobank纵向多模态基准上让紧凑VLM自主选择就诊、器官、模态、切片与专科工具进行推理。

> 🔗 **与课题**：逐环节对照：③能力迁移——把14,734条前沿模型交互轨迹SFT进紧凑策略模型，再在其自身环境交互上RL，是标准的"源(teacher模型/源环境)→目标(learner)"工作流知识迁移实证，与GEE→QGIS迁移在同一方法论层面同构；①工作流推理——agent自主决定查哪次随访、哪个器官、哪种模态、哪张切片、用哪个工具，正是任务分解与步骤规划；④grounding——tool-use harness要求把推理落到具体专科工具调用上，且刻意不规定工具序列，等价于"不给显式中间层、直接落地到operator"的设定；⑥训练/后训练——SFT+agentic RL+特权on-policy自蒸馏+rubric LLM反馈，是一套可直接借鉴的后训练配方；⑦评测——50,401题的纵向多模态基准与"匹配评测条件"，为过程性评测与transfer retention度量提供范式。

💡 **启发**：可直接偷两点：一是用前沿模型与环境交互轨迹做SFT来迁移工作流（而非迁移答案），对应我们的GEE轨迹→QGIS工作流迁移数据构造；二是"不规定工具序列、只用rubric式结果反馈+特权on-policy自蒸馏"来内化证据→结论推理，这恰是不依赖显式L3语义中间层的一种可行训练协议。

### 🔥 ⭐⭐⭐⭐ GeoAgent: An Agent-Based QGIS Plugin for Natural-Language-Driven Geospatial Analysis with Multi-Backend Large Language Model Support

*入选：强命中*

> 📄 **摘要**：Geospatial analysis is essential across the earth and environmental sciences, yet conventional geographic information systems (GIS) rely on a procedure-oriented paradigm that demands substantial operational expertise. We present GeoAgent, an open-source QGIS plugin that enables goal-driven geospatial workflows through natural language conversation powered by large language models (LLMs). GeoAgent features two operating modes: a General mode for exploratory querying and layer management, and a Processing mode for multi-step workflow execution. Built on LangGraph state machines, the system decomposes requests into dependency-ordered task queues, discovers algorithms across the entire QGIS Processing registry (~250+ native, GDAL, GRASS GIS, and SAGA tools) via lexical scoring on LLM-generated keywords, introspects parameter schemas at runtime, and executes workflows with LLM-steered error diagnosis and retry loops. Schema-validated structured outputs ensure consistent performance across interchangeable cloud (OpenAI, Google Gemini, Anthropic) and local privacy-preserving (Ollama) backends. We demonstrate GeoAgent through a reproducible flood-exposure screening case study using a bundled dataset and compare its architecture against existing LLM-GIS integrations. GeoAgent is released under the MIT license on the official QGIS Plugin Repository.

**一句话**：提出开源 QGIS 插件 GeoAgent，用 LangGraph 状态机 + LLM 把自然语言目标分解为依赖有序任务队列，并在 QGIS Processing 全量注册表中检索算子、自省参数、执行并纠错重试。

痛点：传统 GIS 是面向过程的范式，需要大量操作专业知识，自然语言驱动的目标式工作流难以落地。方法：GeoAgent 以 LangGraph 状态机为核心，将用户请求分解成依赖有序的任务队列，用 LLM 生成关键词在 ~250+ 原生/GDAL/GRASS/SAGA 工具上做词法打分检索算子，运行时自省参数 schema，并靠 LLM 引导错误诊断与重试循环执行；结构化输出经 schema 校验以支持云（OpenAI/Gemini/Anthropic）与本地（Ollama）后端互换。结果：用捆绑数据集做洪水暴露筛查的可复现案例研究，并与已有 LLM-GIS 集成做架构对比，MIT 许可发布于官方 QGIS 插件库。

💡 **启发**：可直接偷两点：一是"LLM 生成关键词 + 词法打分"在超大规模算子库（250+）中做 grounding 的检索策略，比纯向量检索更适合算子名/别名场景；二是把算子参数 schema 运行时自省当作生成后校验器，天然抑制幻觉算子与非法参数——这正好可用于我们的幻觉算子率指标与约束解码模块。

⚠️ **局限**：仅为预印本+单案例（洪水暴露筛查）演示，没有量化评测、消融或迁移保持率/执行成功率的系统性基准，引用时不能当作能力证据，只能当作系统设计基线。

🚨 **为什么必须重视**：与核心科学问题的目标端（QGIS operator grounding + 结构化 QGIS 图生成）高度重叠，且已开源上架官方插件库，若不引用/不对比，审稿人会直接质疑工作新颖性与必要性；它给出了 NL→QGIS 工作流端到端可跑的实现路径，等于替我们验证了目标端可行性，也划定了"不做迁移/不训练模型"的差异边界；其算子检索+参数自省+重试纠错管线可作为我们 QGIS 落地可用率与幻觉算子率评测的现成对照基线。

### ⭐⭐⭐ Code Detectors Have a Half-Life: Obsolescence and Metric Illusions in LLM-Generated Code Detection
**6/10** · Alberick Euraste Djire · arXiv · 2026-10-01 · [原文](https://arxiv.org/abs/2610.01664v1) · [PDF](https://arxiv.org/pdf/2610.01664v1)
*入选：能力迁移*

> 📄 **摘要**：Code detectors can become obsolete as code-generating models evolve: a detector validated on one generation of models may not transfer to the next. We call this limited useful life a detector half-life. We evaluate eight general-purpose LLM judges and three dedicated detectors on human-written code and code produced by seven generators across C++, Java, and Python. Our results reveal two problems. First, performance varies considerably across generators and prompting strategies, suggesting that some detectors rely on generator-specific patterns rather than general evidence of code provenance. Second, accuracy can conceal severe prediction bias. DetectCodeGPT and GPT-Sniffer achieved an accuracy of 0.50 but an F1 score of 0.00 across all generators because they classified almost every sample as AI-generated. However, general-purpose LLM judges achieved stronger accuracy and F1 scores. Our results show that general-purpose LLMs are promising training-free judges of code provenance and can outperform dedicated detectors. However, their reliability depends on the judge model, the code generator, and the prompting strategy. We therefore recommend evaluating LLM judges across multiple generators and reporting macro-F1 alongside class-specific precision and recall.
