### ⭐⭐⭐ AI Meets Program Analysis: Lessons from a Decade of Enterprise Software Modernization at IBM
**6/10** · Vini Kanvar · 预印本 · 2026-10-08 · [原文](https://doi.org/10.1145/3843775.3844546)
*入选：工作流×工具推理*

> 📄 **摘要**：Generative AI has rapidly transformed software engineering through code generation, explanation, translation, documentation, and agentic development workflows. This transformation raises a fundamental question: what is the role of program analysis in the era of AI? Drawing on a decade of enterprise software modernization research at IBM, this paper argues that AI and program analysis are not competing technologies but complementary capabilities. Program analysis provides semantic evidence, dependency reasoning, correctness guarantees, and architectural constraints, while AI leverages this evidence to generate code, produce documentation, derive specifications, assist architectural design, and improve developer productivity. We illustrate this synergy through IBM's modernization research spanning legacy software understanding, business function extraction, service refactoring, APIfication, code generation, COBOL-to-Java translation, and automated testing. Across these workflows, a consistent lesson emerges: the most reliable and trustworthy AI-assisted modernization is achieved when AI is grounded in semantic artifacts extracted and validated through program analysis. Looking ahead, we envision enterprise software engineering as a collaboration in which program analysis provides evidence, AI provides intelligence, and human engineers contribute the judgment and wisdom required to build trustworthy software systems.

**一句话**：基于 IBM 十年企业软件现代化研究经验，论证程序分析与生成式 AI 是互补能力而非竞争关系，AI 应被程序分析抽取的语义证据所 grounding。

痛点：生成式 AI 在代码生成/翻译/文档/智能体开发流程中快速普及，引发"程序分析在 AI 时代还有何用"的疑问。方法：以 IBM 在遗留系统理解、业务功能抽取、服务重构、APIfication、COBOL-to-Java 翻译、自动化测试等十年现代化项目为素材，做经验性论证与展望。结论：最可信的 AI 辅助现代化来自"AI 由程序分析抽取并验证的语义工件 grounding"，程序分析提供证据/依赖推理/正确性保证/架构约束，AI 提供智能，人提供判断。

> 🔗 **与课题**：支撑环节②（Workflow→结构化表示）：论文强调依赖推理（dependency reasoning）与架构约束作为生成的结构性证据；支撑环节④（Operator 落地/grounding）：核心主张即"AI 必须被语义工件 grounding 才可信"，与 QGIS operator grounding 的思路同源；间接涉及环节③（跨域迁移）：COBOL→Java、legacy→service、APIfication 属于跨语言/跨表示的代码与 API 迁移实例，可类比 GEE→QGIS 的跨平台迁移。但本文是经验总结与愿景文（lessons/vision），非实证研究，也未涉及 LLM 工作流推理或基础模型能力迁移的量化评测，因此不构成高分支撑。

💡 **启发**：可借鉴其"程序分析产出语义证据→AI 消费证据→约束下的生成"三段式架构，作为我们"是否必须显式 L3 语义中间层"这一核心争点的反方论据与对照框架：把"无显式语义层"的 Route-2 与"强 grounding 于语义工件"的路线做消融对比。

⚠️ **局限**：属立场/经验展望类论文，缺乏受控实验与量化指标（迁移保持率、执行成功率等），且语境为企业软件现代化，不能直接外推为 GIS 工作流结论。

### ⭐⭐⭐ GeoAct: evaluation materials for action-level access control in a geospatial LLM agent
**6/10** · Ehsan Khoramshahi · Zenodo (CERN European Organization for Nuclear Research) · 2026-10-09 · [原文](https://doi.org/10.5281/zenodo.23257543)
*入选：强命中*

> 📄 **摘要**：Evaluation materials for the paper "GeoAct: action-level access control for agentic geospatial analysis with local large language models". GeoAct is a geospatial agent that plans and executes spatial-analysis tool calls on behalf of a user in a multi-tenant spatial data infrastructure. Every tool invocation is authorised against the user's dataset-level permissions before the tool reaches storage, by a deterministic gate called the Action-Level Access-Control Enforcement Point (Action-PEP). This deposit holds the mechanism, the evaluation behind the paper, and the generators for every table and data figure in it. Contents: - code/tools.ts - the read-only GIS tool set and the dataset arguments each tool declares, which is what the Action-PEP gates. Contains the gate itself.- code/agent.ts - the Planner-Action-PEP-Executor loop. Every tool call is authorised before dispatch; denials are counted and audited.- code/geoact_bench.ts - GeoAct-Bench: builds the per-tenant plans, generates the legitimate and adversarial requests together with their ground truth, runs every condition over every planner model, and writes the results and tables.- code/geoact_conformance.ts - the gate-level harness, which needs no language model. Arm A sweeps every (tool, dataset-argument, user, dataset) combination through the enforcement path and checks both directions, unsound execution and over-blocking. Arm B injects plausible defects - bypass mutants that make the gate reach fewer arguments than it should, and policy mutants that weaken its access predicate by one disjunct - and repeats the sweep unchanged.- code/geoact_testbed_export.ts - exports the study-area geometry, transforming the stored WGS84 extents to ETRS89 / TM35FIN in PostGIS.- data/geoact.json - request-level results: unauthorised-access counts and rates per model and condition, content-leak counts, task success, mean steps, mean latency, gate overhead, and the catalogue composition.- data/geoact_conformance.json - gate-level results: per-tool conformance counts with Wilson intervals, and the outcome of every mutant.- data/testbed_extents.json - one projected bounding box per site and tenant. Tenants are anonymised to letters; no dataset names, owners or contents are included.- tables/ - the result tables as they appear in the paper, and make_tables.py, which regenerates all of them from the two result files.- figures/ - make_gate_spectrum.py and make_testbed_map.py, which regenerate the gate-spectrum figure and the study-area map from the data files. Scope and limits: the Action-PEP itself, which is the object of the paper's claim, is included in full, so the gate's placement and logic can be audited directly, and every number in the paper's tables and data figures derives from the files in data/. The conformance and mutation arms are deterministic and need no language model. They still require the live catalogue for the permission relationships, so they cannot be run from this deposit alone, but they involve no sampling: given the same catalogue they return the same counts. The mutation logic can be audited against tools.ts directly, since what it manipulates is the datasetArgs declaration that the Action-PEP reads. A synthetic catalogue is included so that the evaluation can be re-run from this deposit alone. fixture/ holds wholly invented datasets, sites and tenants reproducing the structure the benchmark depends on - disjoint private holdings per tenant, sites where two tenants hold different products over the same ground, a few published datasets - and, unlike the live catalogue, access granted through both the per-user and the per-group route. Load it into any PostGIS database and point the harness at it. Against the fixture all eleven mutants are detected, where the live catalogue detects nine, so the limitation reported in the paper belongs to the testbed rather than to the harness. No real dataset, site, holding or person is represented. The benchmark cannot be re-run against the live catalogue. The harness queries a live geoportal database for the catalogue, its geometries and its permission relationships, and drives a locally served language model; neither is included, because the catalogue contains access-controlled datasets belonging to identifiable researchers and the permission structure between them is the object of the study. The two arms were run on different catalogue snapshots. The request-level benchmark reports the July 2026 catalogue; the conformance and mutation sweeps were run later. Both snapshots are recorded in the respective JSON files. The request-level results are aggregates rather than per-request records. The harness retains counts and rates per model and condition, not the individual adversarial requests, the tool calls the planner emitted, or the agent's answers. Licensing: code under code/ is MIT. The data, tables and figure generators are CC BY 4.0.

**一句话**：GeoAct 是一个面向多租户空间数据基础设施的地理空间 LLM 智能体，在每次 GIS 工具调用前用确定性的动作级访问控制门（Action-PEP）按用户数据集权限授权，并发布配套评测材料。

痛点：LLM 智能体代表用户规划并执行 GIS 工具调用时，若缺乏细粒度授权会造成越权访问，且需要在工具触达存储前拦截。方法：在 Planner–Action-PEP–Executor 循环中，每次工具调用先经确定性门按数据集级权限校验，拒绝被计数与审计；同时提供 GeoAct-Bench（生成合法与对抗请求及真值）和门级一致性测试（穷举工具×数据集参数×用户×数据集组合，并注入绕过变异体）。结果：公开了机制实现、评测流程以及全部表格与图的生成器。

> 🔗 **与课题**：主要支撑环节⑦（评测）：其"合法/对抗请求生成 + 真值 + 穷举式一致性扫描 + 变异体缺陷注入"是一套可直接迁移的评测协议模板，可用于工作流推理质量、执行成功率与错误分析。也支撑环节④（工具落地）的一个侧面：它定义了只读 GIS 工具集与每个工具声明的数据集参数，并在调用前做确定性校验，等价于对"算子/工具调用是否合法可执行"的落地判定与兜底。环节①只有弱关联——Planner 会分解任务并调度工具调用，但规划质量只是被评测的背景，不是研究变量。与②结构化/DAG 生成、③跨平台能力迁移、⑤QGIS 图生成、⑥训练/后训练均无实质关联。

💡 **启发**：可借用其"工具参数声明 + 调用前确定性校验 + 穷举组合扫描 + 变异体注入"的设计，为 QGIS operator grounding 构建一个"依赖闭合/幻觉算子/过度拒绝"三向校验器，用组合扫描与缺陷注入量化落地可用率与幻觉算子率。

⚠️ **局限**：研究焦点是安全授权而非工作流推理或能力迁移，规划质量并非自变量；且这只是评测材料 deposit，引用时应以原论文为准。

### ⭐⭐⭐ Multi-agent reasoning for authentic traditional Chinese painting synthesis
**6/10** · Dandan Qin、Pengfei Jing · Scientific Reports · 2026-10-09 · [原文](https://doi.org/10.1038/s41598-026-74735-6)
*入选：领域×任务*

> 📄 **摘要**：Generating Traditional Chinese Paintings (TCPs), also known as Guohua, remains challenging because such paintings are governed not only by visual appearance but also by culturally grounded principles of composition, brushwork, and symbolic intent. Contemporary text-to-image (T2I) systems can imitate ink textures, yet they often fail to preserve principles such as Liu Bai (functional blankness), Qi Yun (spirit resonance), and context-dependent Cun-fa texturing. We propose MAC-Guohua, a Multi-Agent Collaborative framework that uses reasoning-to-synthesis to translate abstract user intent into structured visual constraints. The framework integrates CP-Knowledge, a retrieval-augmented knowledge base used in a retrieval-augmented generation (RAG) workflow for Chinese painting theory, specialized agents for intent analysis, composition planning, and regional brushwork specification, and a controllable SDXL-based visual synthesizer guided by segmentation ControlNet and a LoRA adapter. To improve reproducibility, we formalize the Knowledge-to-Layout (K2L) mapping module, describe the intermediate layout representation, provide the DOI-archived CP-5K release with train, validation, and held-out test split files, release the implementation code, and evaluate the framework on disjoint training, validation, and held-out test splits. Experiments on the CP-5K dataset show improved performance over the evaluated GAN-based, SDXL-based, and ControlNet-based baselines, achieving an FID of 15.28, a CLIP score of 31.45, and a Negative Space Ratio (NSR) error of 2.1% on the held-out test set. Additional ablations, prompt-fairness baselines, convergence statistics, and latency analysis further clarify the contribution and cost of each component. Expert evaluations indicate that MAC-Guohua improves perceived compositional balance, brushwork authenticity, and cultural plausibility. The implementation code and evaluation scripts are available at https://github.com/pfeijing/mac-guohua.git , and the DOI-archived CP-5K dataset release is available at https://doi.org/10.5281/zenodo.21938347 .

**一句话**：提出 MAC-Guohua 多智能体协同框架，将抽象用户意图经意图分析、构图规划、区域笔法指定等 agent 转化为结构化视觉约束，并形式化 Knowledge-to-Layout 中间布局表示来驱动 SDXL 生成国画。

痛点：T2I 系统能模仿水墨纹理，却难以保持留白、气韵、皴法等文化性构图原则。方法：用 RAG 知识库（CP-Knowledge）加多智能体（意图分析/构图规划/区域笔法）做 reasoning-to-synthesis，产出可复现的中间布局表示（K2L 映射），再由 ControlNet+LoRA 可控合成。结果：在 CP-5K 数据集上 FID 15.2，优于 GAN/SDXL/ControlNet 基线，并开源代码与数据划分。

> 🔗 **与课题**：主要支撑环节①与②：多智能体把抽象意图分解为意图分析→构图规划→区域笔法指定的显式子任务链，属于任务分解与流程规划（①）；Knowledge-to-Layout 模块把规划结果落成形式化的中间布局表示，正是'规划→结构化表示'这一环（②）。但其结构化对象是绘画布局约束而非工作流图/DAG，也未涉及跨平台能力迁移（③）或工具/算子 grounding（④⑤），与 QGIS 场景无直接关系。第⑥⑦环节仅有常规 SFT/LoRA 微调与 FID 评测，不构成本课题关注的方法贡献。

💡 **启发**：可借鉴其'多智能体分工 + 显式中间表示'的两段式设计：用一个独立 agent 专职产出并形式化中间结构（layout/schema），再交给下游执行器——这对应我们 Workflow→结构化 QGIS 图 的分离式管线，中间表示可与评测解耦、便于复现与错误定位。

⚠️ **局限**：属特定视觉生成领域的应用型框架，评估仅用 FID 等图像指标，缺乏对规划质量、结构正确性、执行成功率的评测，方法论外推需谨慎。

### ⭐⭐ EvaLooop : A Self-Consistency-Centered Framework for Assessing Large Language Model Robustness in Programming
**5/10** · Sen Fang、Weiyuan Ding、Mengshi Zhang、Zihao Chen、Bowen Xu · ACM Transactions on Software Engineering and Methodology · 2026-10-08 · [原文](https://doi.org/10.1145/3850240)
*入选：工作流×工具推理*

> 📄 **摘要**：Motivation: Evaluating the programming robustness of large language models (LLMs) is paramount for ensuring their reliability in AI-based software development. Existing robustness assessments commonly employ exogenous adversarial perturbations, where modifications are crafted externally and applied to the model input. Two limitations follow. First, different exogenous attack strategies can produce different rankings across models, making conclusions dependent on the perturbation setting. Second, these assessments do not directly characterize stability when a model's own outputs are transformed and reused as inputs. This setting is relevant to iterative software engineering workflows. Solution: We introduce EvaLooop , a novel assessment framework that evaluates robustness from a self-consistency perspective, leveraging the natural duality inherent in software engineering tasks ( e.g., code generation and code summarization). EvaLooop establishes a self-contained feedback loop where the same LLM iteratively transforms between code and natural language, producing endogenous transformations from its own output distribution. Robustness under these self-generated transformations is quantified by the Average Sustainable Loops (ASL) metric, a normalized score combining quadratically weighted successful-loop counts with semantic similarity. This cyclical strategy identifies when generated code first fails functional tests and provides a complementary view of robustness within the evaluated loops, without requiring external attack configurations. Results: We evaluate 96 popular LLMs, ranging from 0.5B to 685B parameters, on EvaLooop equipped with the MBPP Plus benchmark, and find that EvaLooop typically induces a 2.65%–47.62% absolute drop in Pass@1 accuracy within ten loops. Stability under self-generated transformations does not always align with initial performance ( i.e., a one-shot query); for instance, Qwen3-235B-A22B-Instruct-2507, despite inferior initial code generation compared to OpenAI's o-series models and DeepSeek-V3, achieves a higher ASL score. Impact: EvaLooop reveals distinct degradation patterns across different models, providing developers with a practical framework for evaluating LLM functional coherence through iterative transformations and offering complementary insights that support more informed model selection decisions. A living leaderboard: https://evalooop.github.io/ .

**一句话**：提出 EvaLooop 评估框架，利用代码生成与代码摘要的任务对偶性构建自洽闭环，用 ASL 指标衡量 LLM 编程鲁棒性。

现有 LLM 编程鲁棒性评测依赖外生对抗扰动，模型排名随攻击策略变化，且无法刻画模型自身输出被回灌为输入时的稳定性。EvaLooop 让同一 LLM 在代码与自然语言之间反复互转形成内生变换回路，用二次加权的成功回路数与语义相似度合成 ASL 指标，并能定位生成代码首次功能测试失败的位置。

> 🔗 **与课题**：主要支撑环节⑦（评测协议/指标设计）：它提供了一种不依赖外生扰动、以模型自生成输出构成闭环的鲁棒性度量范式，可迁移为对本课题 transfer retention、多轮重生成结构稳定性的评测思路。与②结构化表示间接相关——其“生成→重解释→再生成”的循环可用于检验 QGIS 图结构在往返转换中的依赖闭合保持情况。但不涉及①工作流推理、③跨平台能力迁移、④operator grounding、⑤processes+links 图生成，也非 GIS/tool 场景，属通用代码生成鲁棒性评测。

💡 **启发**：可把“代码↔自然语言”自洽闭环改造为“workflow 表示↔结构化 QGIS 图”的往返回路，用 ASL 式归一化指标量化依赖闭合保持率与多轮重生成下的结构退化（幻觉算子累积失败点）。

⚠️ **局限**：方法强依赖代码生成/摘要这对天然对偶任务，未触及工作流、工具调用与跨域迁移，指标依赖语义相似度模型且域外适用性未验证。
