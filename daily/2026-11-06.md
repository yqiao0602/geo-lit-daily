### 🔥 ⭐⭐⭐⭐ GeoFaham: Domain-Specialized Multi-Agent Geospatial Analytics for Disaster Response
**8/10** · Muhammad Sohail Danish、Gilles Hacheme、Akram Zaytar、Satej Soman、Inbal Becker‐Reshef、Juan Lavista Ferres · arXiv (Cornell University) · 2026-11-03 · [原文](https://doi.org/10.48550/arxiv.2611.04977)
*入选：工作流×工具推理*

> 📄 **摘要**：Real-world geospatial decision support requires more than single-step retrieval or code generation. Disaster-response questions often involve multi-source workflows that combine spatial databases, map-derived features, satellite imagery, raster products, and reusable geospatial artifacts, where correctness depends on preserving spatial scope, temporal context, and intermediate execution state. While large language models and coding agents offer a promising interface for such workflows, they struggle with geospatial-specific failure modes, including handling large artifacts, selecting the wrong evidence source, losing spatial or temporal metadata, and applying invalid geometric operations. We introduce GeoFaham, a domain-specialized multi-agent system for geospatial disaster analytics. GeoFaham decomposes workflows into specialist agents for vector operations, map feature retrieval, imagery discovery, and raster analysis, coordinated by an Orchestrator with a dual-ledger control loop for dependency-aware planning, progress tracking, validation, and replanning. To support artifact-centric collaboration, GeoFaham uses a Response Store that persists full geospatial outputs and typed metadata outside the LLM context window while agents exchange compact identifiers and summaries. We also introduce GeoFaham-Bench, a 40-task benchmark grounded in 17 real-world disaster records, designed to evaluate multi-step geospatial reasoning, cross-source integration, raster-vector computation, artifact generation, and recovery under non-rigid ground truth. We evaluate GeoFaham on GeoFaham-Bench against strong general-purpose coding-agent baselines, including Codex, Claude Code, and OpenCode. GeoFaham achieves the best overall performance, scoring 0.940 versus the next-best 0.879, while using 7.5 times fewer tokens. Our code and benchmark are publicly available at https://github.com/microsoft/GeoFaham.

**一句话**：提出 GeoFaham——面向灾害响应的领域专用多智能体地理空间分析系统：由 Orchestrator 通过双账本控制环进行依赖感知规划、进度跟踪、验证与重规划，调度矢量、地图要素、影像发现、栅格等专家智能体，并用 Response Store 在上下文外持久化完整地理空间产物与类型化元数据；同时发布基于17条真实灾害记录的40任务基准 GeoFaham-Bench。

痛点：真实地理空间决策支持需要跨空间数据库、地图要素、卫星影像、栅格产品的多源工作流，正确性取决于空间范围、时间上下文与中间执行状态的保持，而 LLM 与代码智能体常出现大产物处理失败、证据源选错、时空元数据丢失、非法几何操作等地理空间特化失效模式。方法：将工作流分解为多个专家智能体，由 Orchestrator 以双账本控制环做依赖感知规划、进度跟踪、验证与重规划，并用 Response Store 在 LLM 上下文窗口之外保存完整产物、智能体之间只交换紧凑标识符与摘要。结果：给出 GeoFaham-Bench（40 任务、17 条真实灾害记录），用于评测多步地理空间推理、跨源集成与栅格-矢量计算。

> 🔗 **与课题**：核心相关，直接支撑①与⑦，并在工程上触及⑤。①GIS Task→Workflow：论文把灾害问题显式分解为矢量操作、地图要素检索、影像发现、栅格分析等子任务，且用『双账本控制环』做依赖感知规划（dependency-aware planning）与重规划，这正是本课题 workflow reasoning 中的任务分解与步骤规划；②Workflow→结构化表示：双账本本质上是对步骤依赖与执行状态的结构化编码，可视为依赖图（DAG）的运行时表示，虽未显式输出 processes+links 图结构；③能力迁移：本文不做跨平台迁移（无 GEE→QGIS、tool→tool 迁移实证），此环节支撑弱；④/⑤：专家智能体把子任务落到具体矢量/栅格算子调用，属于 operator grounding 的雏形，但算子层面是 Python/地理空间库而非 QGIS processes 图；⑦评测：GeoFaham-Bench 提供了多步地理空间推理与跨源集成的任务设计范式与错误模式分类（证据源选错、时空元数据丢失、非法几何操作），可直接映射为本课题的幻觉算子率、依赖闭合率、执行成功率指标。整体上它是『GIS workflow reasoning + 智能体编排 + 评测基准』的直接同类工作，但不涉及模型内部可迁移知识的训练/后训练与 QGIS 落地。

💡 **启发**：可直接借鉴两点：一是『双账本』（依赖账本+进度账本）控制环——把工作流的依赖关系与执行状态分离记账，用于生成 QGIS processes+links 图时保证依赖闭合与可重规划；二是 Response Store 的『大产物外置+智能体间只传紧凑类型化标识符与摘要』模式，正好对应本课题『不依赖显式 L3 语义中间层、但仍需保住空间范围/时间上下文/中间状态』的设计张力。

⚠️ **局限**：属于智能体系统工程与基准构建，不含任何模型训练/后训练或跨平台迁移实验，算子落地停留在 Python 地理空间库而非 QGIS processes 图，且基准仅40任务、依赖较强的闭源 LLM 后端。

🚨 **为什么必须重视**：这是与本课题核心科学问题正面接近的一类工作：同样研究地理空间任务的工作流分解、依赖感知规划与执行状态保持，并自带评测基准，若不及时对标，评测协议与『依赖账本』这一结构化表示思路可能被其先占。它同时可作为本课题 QGIS grounding 管线最直接的对比基线——其失败模式分类可直接转成我们的幻觉算子率与依赖闭合指标。其 Response Store 设计也提示了如何在放弃显式 L3 语义层的情况下仍保持中间状态与时空元数据，这一点必须尽快验证可否迁移到 QGIS 图生成。

**▸ 建议：精读**

### ⭐⭐⭐⭐ A Self-Exploring and Self-Evolving Paradigm for Adaptive Edge AI Development
**7/10** · Leming Shen、Qiang Yang、Xinyu Huang、Zijing Ma、Yuanqing Zheng、Chris Xiaoxuan Lu · arXiv (Cornell University) · 2026-11-01 · [原文](https://doi.org/10.48550/arxiv.2611.01377)
*入选：工作流×工具推理*

> 📄 **摘要**：Large Language Models (LLMs) exhibit powerful code generation abilities, fostering agentic systems to automate edge AI application development. However, existing agents typically operate via fixed agentic workflows and predefined design spaces, struggling to handle rapidly evolving demands of real-world scenarios (e.g., heterogeneous data modalities, diverse task pipelines). Unlike prior systems that treat LLMs mainly as code generators following rigid workflows, we fully exploit their reasoning capabilities to allow agents to determine their own workflows on the fly. To this end, we propose SE2, a self-exploring and self-evolving paradigm for adaptive edge AI development. Inspired by human learning processes, we distill development into four atomic operations (retrieve, reason, code, test), and empower agents to explore workflows by dynamically and adaptively selecting an appropriate next operation based on the current context. Extensive evaluations show that, with adaptive workflows, the synthesized programs achieve up to 26% higher accuracy and consume 28% lower resources than state-of-the-art baselines, while maintaining superior adaptability to unforeseen edge AI scenarios. This highlights the potential of reasoning-driven adaptive agentic workflow in edge AI development.

**一句话**：提出 SE2 范式：把开发过程拆成 retrieve/reason/code/test 四种原子操作，让 LLM 智能体根据当前上下文动态选择下一步操作，从而自主探索并演化工作流，用于自适应边缘 AI 应用开发。

痛点：现有智能体依赖固定的 agentic workflow 和预定义设计空间，难以应对异构数据模态、多样任务管线等快速变化的真实需求。方法：借鉴人类学习过程，将开发蒸馏为四个原子操作，让智能体在运行时自适应选择下一步操作、自行决定工作流，而非把 LLM 仅当代码生成器。结果：合成程序准确率最高提升 26%、资源消耗降低 28%，且对未见过场景适应性更强。

> 🔗 **与课题**：主要支撑环节①（Workflow Reasoning：任务分解与步骤规划）与②（Workflow→结构化表示：动态编排操作序列）；并涉及⑦评测（跨场景适应性、准确率/资源指标）。其核心主张"放弃固定工作流、由模型自行决定 workflow"与课题 Route-2 的"模型内部可迁移的工作流知识"高度同源，可作为"workflow 不是硬编码模板而是模型可自主学习的能力"的论据。但它是边缘 AI 部署应用语境，未做 GEE→QGIS 类跨平台迁移实证，也未产出依赖闭合的图结构（processes+links），故未达 8 分。

💡 **启发**：可借用其"四原子操作 + 上下文自适应选择下一步"的极简操作集设计，把 GIS 工作流同样蒸馏为少量原子算子序，并让模型动态选择序，用于检验 workflow knowledge 是否稳定；其跨未见场景的适应性评测协议也可迁移为 transfer retention 测试。

⚠️ **局限**：属系统/应用导向工作，缺少对"工作流知识如何在模型内部形成并可迁移"的机制分析与消融，且无 GIS/工具 grounding 与结构化图正确性指标。

**▸ 建议：略读**

### 🔥 ⭐⭐⭐⭐ Grounding in the Dark: Text-Only Training for Zero-Shot Video Temporal Localization
**8/10** · Divyanshu Mishra、Sabine Sternig、Rakshith Shetty、Erhan Gundogdu · arXiv · 2026-11-04 · [原文](https://arxiv.org/abs/2611.06149v1) · [PDF](https://arxiv.org/pdf/2611.06149v1)
*入选：能力迁移*

> 📄 **摘要**：Video-LLMs are typically trained on paired video-text data for temporal tasks, yet collecting precise temporal annotations and training on large-scale video datasets are both costly. We investigate whether a text-only LLM, with no vision-language pretraining, can be trained on textual video descriptions alone to perform temporal grounding and receive video only at inference time. This setting removes paired video data from training altogether and is a step toward training multimodal models without paired annotations. We generate a 134K-example corpus of textual sequences with up to 100 time steps, adapt Qwen3-8B with LoRA on CLIP or LLM2CLIP text embeddings, and evaluate on Charades-STA and QV-Highlights without training on videos from either benchmark. LLM2CLIP, whose text encoder supports longer inputs, represents detailed descriptions better than CLIP (61.54 versus 53.86 mtIoU on Temporal-TextVid) and transfers them better to video. Still, replacing text with frame embeddings at inference yields only 4.99 mtIoU on Charades-STA and 11.12 on QV-Highlights, revealing a large modality gap. To bridge it, we propose Nearest Entity Replacement (NER), a training-free mapping that represents each video frame by the normalized mean of its nearest text-entity embeddings, so that the model receives the kind of input it was trained on. NER reaches 14.45 mtIoU on Charades-STA and 20.72 on QV-Highlights, outperforming the strongest of four families of modality-gap baselines by 5.00 and 1.71 points. NER thus enables partial transfer from text to video, while more reliable grounding will likely require encoders with better-aligned text and visual representations.

**一句话**：本文研究仅用纯文本训练的 LLM 能否零样本迁移到视频时序定位，并提出一种无需训练的最近实体替换（NER）方法来弥合模态鸿沟。

痛点：视频时序标注与大规模视频-文本配对数据都极其昂贵，能否仅靠文本描述训练、推理时才见视频？方法：作者构建 13.4 万条、最长 100 个时间步的纯文本时序序列语料，在 CLIP/LLM2CLIP 文本嵌入上用 LoRA 适配 Qwen3-8B；推理时把文本替换为帧嵌入，并提出 NER：将每帧表示为最近的文本实体嵌入的归一化均值，使模型收到与训练时同类的输入。结果：直接替换帧嵌入时迁移损失严重（Charades-STA 4.99、QV-Highlights 11.12 mtIoU），NER 将其提升到 14.45 与 20.72，超过四类模态鸿沟基线中最强方法的 5.00 与 1 以上。

> 🔗 **与课题**：主要支撑第③环节（源域→目标域能力迁移）：该文正是"只在源域（文本）训练、零样本迁移到目标域（视频）"的实证研究，并给出迁移保持率的量化方式，与本课题中 GEE 训练、QGIS 落地之间的跨平台迁移问题同构。第④环节（Workflow→QGIS Operator grounding）：NER 是一种无需训练的输入重映射，把目标域单元（frame）表示为源域实体（text entity）的聚合表示；类比其做法，可把 QGIS 算子按语义描述映射回 GEE 语料中训练时见过的实体表示，作为 grounding 前的一致性对齐层，从源头降低幻觉算子率。第⑤环节（结构化图生成）：文中把时序定位建模为对 100 个时间步位置序列的输出，和 processes+links 的依赖图输出一样，都属于对结构化解码的约束问题。第⑦环节（评测）：作者设计四类模态鸿沟基线的对照协议并报告 mtIoU 保持率，可直接借用为"迁移保持率"的评测骨架，用于比较 QGIS 落地可用率与执行成功率。第②⑥环节为间接支撑：文本化序列是一种中间结构化表示，LoRA 适配是该文唯一的训练手段。

💡 **启发**：借鉴 NER 的 "无需训练、按最近实体重映射输入" 思路：先检索 GEE 工作流语料中最接近的算子语义实体，再用它们的嵌入均值构造 QGIS 算子的输入表示，使模型在不重训的情况下仍面对训练时见过的输入分布，从而提升 landing 可用率；同时借用它的四族 gap baseline 设计来量化迁移保持率。

⚠️ **局限**：该文只做时序定位这一任务，迁移后仍有巨大残差（14.45 mtIoU），且高度依赖 CLIP/LLM2CLIP 文本编码器的表征质量，不能直接等价于工作流推理能力的迁移。

🚨 **为什么必须重视**：该文是"零样本源域→目标域迁移 + 免训练输入桥接"最贴近的方法论参照，正对准课题第③环节（能力迁移保持率）的核心；其 NER 做法与 migration-retention 评测协议可低成本直接搬到 GEE→QGIS 落地实验；若不及早纳入，QGIS grounding 环节会缺少一个可对照的强迁移基线。

**▸ 建议：对比基线**

### ⭐⭐ How Far Can You Steer? Behavior-Capability Frontiers in Contrastive Activation Addition
**5/10** · Deepanshu Raj · arXiv · 2026-11-04 · [原文](https://arxiv.org/abs/2611.06001v1) · [PDF](https://arxiv.org/pdf/2611.06001v1)
*入选：能力迁移*

> 📄 **摘要**：Activation steering can modify language-model behavior without parameter updates, but behavioral efficacy alone does not determine whether an intervention is usable. Contrastive Activation Addition (CAA) steers targeted behaviors using activation directions derived from contrasting examples, potentially degrading unrelated model capabilities in the process. We therefore study CAA through a behavior-capability frontier, selecting interventions that maximize behavioral gain subject to an explicit bound on capability degradation. We evaluate this framework across four instruction-tuned models, seven behaviors, and capability-loss budgets of 1%, 3%, and 5% (absolute percentage points). Validation-selected behavioral effects generalize strongly to held-out data ($ρ= 0.945$), while joint behavior-capability survival among nonzero operating points rises from 37.5% at the 1% budget to 72.7% at 3%, with limited additional improvement at 5%. Control experiments indicate that these effects depend on learned behavior directions rather than generic activation perturbations. Representational geometry is significantly but only modestly predictive of causal cross-behavior transfer. Finally, secondary capability, out-of-distribution, and open-ended evaluations show that interventions satisfying protected benchmarks can still degrade untested capabilities or transfer unevenly to free-form generation. These results characterize activation steering as a constrained intervention whose usable range depends on model, behavior, direction, layer, and evaluation budget, rather than a universal control knob.

**一句话**：研究对比激活加法（CAA）的"行为—能力边界"：在显式限制能力损失的前提下选择激活干预方向，并跨4个指令微调模型、7种行为评测其可用范围。

痛点：激活引导无需更新参数即可改变模型行为，但行为有效并不等于干预可用——CAA 可能在改变目标行为的同时损害无关能力。方法：把 CAA 表述为约束优化，在1%、3%、5%（绝对百分点）的能力损失预算下最大化行为增益，并检验验证集选择的外推性、表征几何对跨行为因果迁移的预测力，以及 OOD 和开放式生成上的二次评估。结果：验证集选出的行为效应在留出数据上泛化很强（ρ=0.945），行为与能力同时存活的非零工作点比例从1%预算的37.5%升至3%的72.7%（5%增益有限）；满足受保护基准的干预仍可能损害未测能力，且向自由生成迁移不均。

> 🔗 **与课题**：主要支撑环节⑦（评测协议：能力损失预算、行为-能力联合存活率、OOD/开放式二次评估、验证集选择的外推检验），其次间接支撑环节③（能力迁移——但这里指激活空间中跨行为的因果迁移，以及用表征几何预测迁移是否发生，与 GEE→QGIS 的跨平台迁移不同构）。与①②④⑤（工作任务分解、结构化/DAG 生成、算子 grounding、processes+links 图生成）无直接关系，也不涉及 workflow/tool 场景。可借用其"增益-损失边界"的度量思想来定义迁移保持率，但不能当作跨平台能力迁移的实证依据。

💡 **启发**：可借"能力损失预算 + 联合存活率"的做法，把"QGIS 落地成功率提升"与"GEE 工作流推理能力下降"放进同一坐标系，用它筛选训练/干预配置；另可参考其用验证集选择效应再在留出集检验泛化（ρ=0.945）的稳健性报告方式。

⚠️ **局限**：干预停留在激活层面、行为集合为通用行为（非多步工具调用/结构化生成任务），结论向自由式生成迁移不均，离工作流级能力证据较远。

### 🔥 ⭐⭐⭐⭐ A Hybrid Approach for Automated Security Pattern Recovery
**8/10** · Anh Minh Nguyen、Tuan Dat Tran、Alzubair Hassan、Liliana Pasquale · arXiv · 2026-11-04 · [原文](https://arxiv.org/abs/2611.05823v1) · [PDF](https://arxiv.org/pdf/2611.05823v1)
*入选：领域×任务*

> 📄 **摘要**：Security-by-design emphasises integrating security into software design and development. Security pattern catalogues operationalise this principle by prescribing reusable architectural solutions to recurring security problems. However, recovering their implementations from source code remains challenging because security patterns are abstract, span multiple components, and admit many valid implementations. We present SecPatRec, a hybrid approach for automated security pattern recovery from source code repositories. We treat a security pattern as a reference architecture and frame its recovery as a deductive task: determining which prescribed roles are present, grounding them in code entities, and recovering their interaction sequences. SecPatRec pairs a ReAct-style LLM agent equipped with semantic and lexical code search for role detection and grounding with static code property graph analysis for interaction recovery. We curate a human-validated ground-truth dataset of 100 pattern instances covering five security patterns across 93 open-source Java and Python repositories, and introduce a three-level evaluation framework measuring recovery correctness against this ground truth. We evaluate SecPatRec using four LLMs, including proprietary and open-source models. Averaged over all models and pattern instances, SecPatRec achieves role-detection accuracy of 0.84, role-grounding similarity of 0.84, and an interaction-recovery score of 0.66. Compared to a one-shot end-to-end LLM baseline, SecPatRec achieves higher aggregate recovery scores and lower estimated LLM API costs per run, while processing repositories that exceed the baseline's configured input limit. The recovered role mappings and statically derived interaction sequences provide structural and behavioural evidence that can support inspection of security-pattern implementations.

**一句话**：提出 SecPatRec，一种混合方法：用带代码搜索能力的 ReAct 式 LLM agent 检测安全模式角色并把角色落地到代码实体，同时结合静态代码属性图恢复角色间交互序列。
